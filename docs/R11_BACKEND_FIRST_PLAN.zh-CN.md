# Local Probe 后端优先开发计划

日期：2026-10-06。计划修订：第 2 版。基线：R10.2-desktop。状态：用户已确认，实施中；七项能力尚未交付完成，真实增量和验证见 [R11 进展记录](R11_BACKEND_PROGRESS.zh-CN.md)。本文中的计划目标不等于已完成事实。

测试约束补充：用户明确要求“不新开账号直接测试”。不创建 Windows 登录账号，也不创建新的外部账号；优先验证当前账号的受限进程和临时 AppContainer 配置（不是登录账号），测试结束清理。此约束不取消文件、网络、子进程隔离硬门，也不授权未受限的用户脚本执行或服务安装。当前账号候选启动失败时如实记录，不能把失败解释为必须新建账号。

后续约束：用户在启动故障修复后选择“仅继续不修改系统策略的测试”。本轮不安装动态 WFP 过滤器，也不修改防火墙/全局系统策略；继续现有权限内的合成文件、子进程和兼容性验证。严格网络门仍未闭合时不开放产品执行，也不将 AppContainer 的丢包/超时当作原定八类 ALE 拒绝能力。

本阶段必须交付七项能力：高级开发者命令运行、工具版本探查、多连接同时运行、高级文件规则编辑、工作文件写入、项目构建与测试、用户自选脚本执行。取消上一版将写文件、构建测试和脚本延后的决定。七项能力首先在后端完成真实实现和验证，再接入现有 GUI，最后进行人工验收。不重做已经认可的页面风格，不把配置开关、模拟测试或启动按钮当作功能交付。

用户最新要求将 MASTER_PLAN 的 P14 写入和项目代码执行提前到本阶段；历史“写入后置”和“仅固定原生命令”的范围限制不再用于排除这三项功能。授权、隔离、预算和审计硬门仍保留。R11 是任务编号，不是已发布版本号。现有 R10.2 程序作为回退基线保留；开发计划的确认不等于自动安装服务、修改系统策略、联网下载依赖、创建凭据、提交、推送或部署的授权。

## 一 本阶段的完成定义

| 必交付功能 | 本阶段要达到的结果 | 不能算完成的情况 |
|---|---|---|
| 高级开发者命令运行 | 已认证连接引用本地批准的固定命令模板；本机逐次确认后，真实执行、取消、超时回收并取得有界结果 | 只能编辑模板；execution_available 仍恒为 false；只有 version_probe 或测试 helper 能运行 |
| 工具版本探查 | 查询本地注册的实际原生工具版本；返回工具 ID、版本、退出状态及明确的失败原因 | 仅检查文件存在；根据文件名猜版本；只有模拟输出 |
| 多连接同时运行 | 至少 A、B 两个独立 MCP/Tunnel 运行实例同时服务；范围、端口、身份、状态、日志和停用互不混淆 | 只能保存多份配置；切换历史项时总是停掉上一条；用两个假进程代替真实连接 |
| 高级文件规则编辑 | 本地增删改 root/profile 的 deny 与 ignore；校验、预览、持久化并使后端实际执行；收紧规则及时撤销旧请求 | 仅展示规则文本；只改变 UI；规则对命令输入不生效 |
| 工作文件写入 | 在单独授予写权限的 root/path 内，真实新建、更新文本文件和应用 patch；修改前预览、本机确认、版本冲突拒绝及可验证恢复 | 只能备份配置；只在临时目录改文件；直接覆盖外部修改；只返回模拟 diff |
| 项目构建与测试 | 在授权项目副本上执行真实 build/test，管理允许的子进程、输出、产物、失败和取消；确认后把批准的产物或修改写回原项目 | 只查询编译器版本；仅启动测试 helper；永远禁止构建必需的子进程；只有模拟 PASS |
| 用户自选脚本执行 | 允许用户选择或新增脚本，不限于预置功能；批准脚本内容、解释器、参数、输入范围和写出范围后真实执行并取得有界结果 | 只允许固定版本探针；只保存脚本配置；偷偷以用户完整权限运行；把不支持的解释器宣称为支持 |

高级模式分为固定命令、脚本、构建测试和写入四类可独立授权的能力。本阶段的“任意脚本”指用户可以选择或新增任意业务内容的脚本，而非只能选预置版本查询；每次执行仍受批准内容和权限约束，不开放未经确认的无限制远程交互式 Shell。

Windows 首批脚本适配器覆盖 PowerShell、Python、Node.js 和 cmd/bat。不存在的运行时需明确告知并提供选择/配置入口，不能自动安装；bash/WSL 和其它解释器按可扩展适配器后续兼容，不承诺所有语言和外部环境都能执行。具体脚本内容可以来自本机选择，也可以来自写入工具刚创建的授权项目文件，但执行前必须重新确认实际内容摘要，写权限不等于执行许可。

联网、下载依赖、读取凭据、系统级操作和文件删除不因上述能力自动授权。默认离线构建和测试；确需下载依赖时单独申请具体目标和操作授权，不把联网失败伪装成构建功能通过。

固定命令必须至少有一个非版本查询的真实只读用途，例如批准的文本检索或统计工具处理授权文件；不能用“版本号能查询”代替高级命令交付。具体可执行文件在兼容性验证时锁定，不为了满足演示自动安装第三方工具。

## 二 代码基线及必须解决的接线问题

- `internal/mcpserver/server.go` 当前注册 11 个只读工具，没有命令调用入口。
- `internal/desktopbridge/developer.go` 只投影和保存授权配置，真实执行保持关闭。
- `internal/commandexec`、`commandprofile`、`confirmation`、`commandpath`、`probe` 已有可复用核心；fixed_command 仍主动拒绝，路径解析和最终执行证明不能被纯 argv 构造替代。
- `internal/networkguard/wfp` 只有固定计划和 DisabledBackend，不能产生真实隔离证明。
- `internal/desktopbridge/service.go` 只持有一个控制器；`previewconnect` 已能启动真实 MCP 与 Tunnel，但尚不是多连接运行时工厂。
- `internal/connectionmanager`、`supervisor`、`admission`、`runtimeowner`、`readiness` 已有协调契约，未形成生产请求和真实进程的完整链。
- `internal/policy/policy.go` 用整份配置 revision 撤销 BoundScope；需要避免改 A 就撤销不相关的 B。
- `internal/config/filestore.go` 明确不是完整生产授权边界。既有 workspaceadmin OS 锁不能自动证明所有新写入口也受保护，需统一写入路径和复测。
- 当前没有工作文件 write_file/apply_patch 后端；配置写入和备份代码不能代替项目文件写入边界。
- `commandprofile` 的现有版本探针限制以短时、单进程为主，没有脚本、构建测试任务契约；不能简单放大原有上限或让解释器混入 version_probe。

优先复用以上模块，补齐真实适配器及失败路径；不并排再造一套命令系统或另一套连接管理系统。

## 三 安全及运行架构

### 1 连接运行时和配置管理

以一个本地后端管理多个 connection runtime。每条连接拥有独立 loopback 端口、凭据引用、MCP 来源、Tunnel 子进程、状态目录和生命周期 epoch。GUI 的“当前选择”只是管理视图选择，不代表其它连接停止。

统一配置文件保留 CAS revision 用于防止覆盖并发编辑；每条连接另外持有有效授权 epoch/投影版本。投影包含该连接实际引用的 profile、roots、deny/ignore、read/write/execute 范围、工具和任务授权、身份及生命周期信息。不可简单跳过现有 revision 校验。

修改 A 的独有规则只撤销 A；修改 A、B 共用的 profile/root/命令模板必须同时撤销受影响连接。无关 B 的文件请求、cursor、确认和运行时不应被错误撤销。metadata-only 编辑是否影响授权须在契约中固定。

配置由单一后端写入：跨进程锁、严格解析、CAS、原子保存、恢复策略、ACL/路径身份复核，以及变更与撤权的一致性必须接在所有管理入口。不得在保存失败后继续使用扩大的权限。

### 2 命令授权和执行

固定命令的远端请求引用 command_id、variant_id 和 typed slots。脚本与构建任务可以提交授权 root 内的入口、任务选择及符合 schema 的参数，由后端形成不可变任务清单；connection/profile 始终来自认证层。不能通过 JSON 中的 confirmed=true 获得授权，也不能指定主机任意 executable、env 或 cwd 绕过本机批准。

每次执行绑定可信 connection、profile、command/task rule、授权 epoch、入口及输入副本摘要、解释器/工具链身份、规范参数、权限范围和一次性确认。脚本修改、任务参数改变、运行时替换或输入副本改变后需要重新确认。命令规则增加逐连接、逐 profile、逐 root 的显式授权映射，避免“勾选连接后就拥有全部模板”。关闭模式、撤销连接、改规则、重启运行时立即使相应待确认和执行许可失效。

默认只读 profile 保留；另加明确的 write/script/build-test capability 与访问模式迁移。需更新当前 BindAuthenticated 的只读假设，并保证旧只读配置继续可用；不能仅翻转 readOnly 使所有文件访问失败，也不能让可写 profile 默认获得执行权限。可读、可写和可执行的路径集合必须分别定义。

后端先提供仅本机可访问的管理 CLI/IPC 来处理确认队列，再接 GUI。远程请求返回 pending_confirmation 和不透明操作 ID；本机确认、拒绝、过期、取消及结果查询构成完整状态机。等待人工确认时不占用执行槽，不允许无界队列。

沿用现有 WFP dynamic-session broker 设计，补齐受限 worker 身份、挂起启动、真实映像复核、Job 归属、网络证明及审计。WFP 只解决网络控制，不能把 cwd 或断网当作文件隔离。

任务输入经当前 BoundScope/rootfs 授权打开，制作有界、可核对内容摘要的私有项目副本；复制扣预算、复核版本并报告未覆盖文件，不默认复制整个磁盘或其它连接的目录。版本探针不读取项目；固定命令默认只读输入；脚本和构建任务可以写明确的副本区域、缓存和产物目录。复制文件时不能忽略硬性 deny；ignore 是否纳入构建输入要由独立 manifest 显式指定并确认，不能借此突破 deny。

原项目修改通过独立 write/apply_patch 后端或任务结果的 write-back 进入：检查写权限，生成 diff/产物清单，本机确认，复核原文件内容版本后落盘。默认不是 live 原目录执行，以便先明确任务实际修改。任务“执行成功”和“已写回”是两种状态；仅改临时副本不算完成工作文件写入能力。直接在原项目上执行不是本阶段必交付模式，不用它绕过隔离难题。

现有单进程 Job 仅适合版本探针。构建和脚本必须有不同资源档位，允许经批准的解释器、编译器及必要子进程树，保持禁止 breakaway、限制进程数/CPU/内存/磁盘/时限，取消时回收整个树。构建产生的测试 executable 也需要在受控身份和副本范围内执行，不能以“无事先固定哈希”为由禁止所有真实测试，也不能因此允许任意主机 executable。动态子进程必须继承文件、网络和任务边界；仅有 Job 回收不算隔离证明。限制参数在实测后冻结，不继续使用版本探针的短时/单进程上限来假装支持 build/test。

任意脚本不能靠静态分析证明无副作用；入口和输入摘要用于确认版本，OS 隔离才用于限制行为。插件、导入模块、package scripts、构建链和 hooks 均视为项目代码执行；只有属于已批准副本与工具链的执行才可发生，不能依赖一句“禁 hooks”来声称其不存在。禁止访问主机秘密目录、项目外写入、连接凭据和未经允许的网络/系统 IPC。

受限身份与文件/注册表访问需单独完成实机证明；AppContainer/LPAC 仅作为具体工具的兼容性验证候选，不假定任意桌面 CLI 都适用。若旧路线无法满足文件访问边界，应先完成架构裁决并向用户说明，不使用 unrestricted fallback。

网络过滤必须绑定到受控 worker 身份，不误伤用户正常运行的同名程序，也不阻断 MCP/Tunnel。过滤器丢失、broker/BFE 异常时，worker 必须仍被阻断或已终止；不能留下先解除网络限制、后继续运行的窗口。

需要安装 broker/service 或授予系统网络对象权限时，单独说明具体服务、权限、安装和卸载影响并取得授权。GUI、MCP 不以管理员身份常驻，不能用 LocalSystem 执行用户命令来绕过权限问题。源码及无特权测试可以提前进行。

### 3 文件规则语义

deny 是访问拒绝，适用于读取、元数据、概览、搜索、写入、patch、脚本与构建输入、产物写回；优先级高于所有 allow/ignore。ignore 只控制发现与搜索，不伪装成保密规则。增加独立 write_allow 与 execute/task scope，不把读取目录授权当成写入/执行授权。

首版只编辑现有 glob 语法，不新增任意 regex/脚本规则。保留 root 和 profile 两层，拒绝非法语法、过量规则及危险的系统范围扩张。规则预览只回答用户提供路径的匹配结果或有界样本，不自动扫描整个磁盘。

规则收紧时撤销受影响的在途/排队读取、cursor、待确认任务和运行中的任务，拒绝尚未提交的写入或写回。取消已完成的写入不能自动回滚其它用户的新修改；恢复需要版本复核和本机确认。共享规则的影响连接在本机确认前列出。

### 4 工作文件写入和恢复

增加 write_file 和 apply_patch：文本文件新建、替换及 patch，支持编码/换行保护、diff 预览、明确的 create-only/expected-content-version 和本机确认。新文件不得默认覆盖已有目标；现有 readcore 的弱元数据版本不作为防覆盖的强内容证明。

写入采用受授权 root 约束的目标打开/临时文件/原子替换方案，并验证 Windows 路径身份、并发改动、链接交换、硬链接和失败清理。不承诺跨文件全局事务；多文件操作返回逐项状态与恢复记录。恢复只覆盖匹配预期当前版本的目标，不“强制还原”用户在其后作出的修改。

工作文件恢复记录与 .lpbackup 配置备份分开管理。原内容和任务产物属于本地敏感数据，设置权限、保存时限、总容量和删除策略，不能混入诊断导出。第一版不默认开放删除、重命名或写任意二进制文件；构建产物以专用有界导出/写回操作处理，覆盖已有产物需要单独确认。

### 5 脚本和构建测试的结果

任务状态明确区分 waiting_confirmation、queued、running、succeeded、failed、timed_out、cancelled、policy_revoked 和 cleanup_failed；成功构建不等于测试通过，更不等于产物已经写回。返回真实退出码、时长、输出截断标记、执行的测试/构建范围和产物清单。

执行日志为有界敏感结果流，仅该授权连接和本机视图可以读取；审计记录只保存摘要及统计，不保存脚本正文、源文件、完整 argv/env/stdout。任务失败不得静默删输出、自动重跑产生副作用或自动回滚用户文件。超限/未发现测试/只运行部分测试须显式报告，不能宣称完整通过。

## 四 执行顺序和任务包

### R11 00 契约和真实隔离验证

对应原计划：P04、P08、P09、P10、提前实施的 P14。

1. 冻结七项接口、schema 迁移、read/write/execute 独立权限、连接授权 epoch、任务清单、CLI 确认和错误码。
2. 区分无特权测试、真实 worker 测试、需管理员的网络测试和需外部凭据的 Tunnel 测试。
3. 在专用临时区域用恶意 native helper 验证文件读取、写入、网络、IPC、子进程及崩溃边界；随后验证两个真实工具版本、非版本固定操作、多文件写入、真实脚本和真实编译/测试流程。
4. 核对 broker 运行身份、映像/依赖访问与 IPC ACL。具体工具不兼容时明确标注 unsupported，不放宽沙箱。

产物：接口与权限契约、隔离裁决、兼容性矩阵和验证记录。隔离未成立时不得删除执行硬门；本阶段必须继续解决该依赖，不能把“仍关闭”标为交付。

### R11 01 配置事务和高级文件规则后端

对应原计划：P04、P09。

1. 统一 config/workspaceadmin 的跨进程管理写入口，完善保存、ACL/路径复核、冲突、回滚和迁移。
2. 加入 root/profile deny、ignore、write_allow 和 execute/task scope 的读取、校验、预览、增删改接口。
3. 接入 per-connection 有效投影、scope epoch、Source 重建和影响集合计算。
4. 撤权覆盖文件请求、search/snapshot cursor、写入/写回和所有任务，不只刷新管理视图；完成旧配置默认只读和新权限 schema 迁移。

验收：CLI 修改后读取/search/snapshot 真正改变；非法规则、旧 revision、保存失败均无新授权；修改 A 不影响无关 B；共享规则同时影响 A/B；规则命中、Windows 大小写、中文路径、`**`、deny/ignore 区别和路径交换攻击通过测试。

### R11 02 多连接真实运行时后端

对应原计划：P09、P10。

1. 将 previewconnect 的真实启动链适配到 connectionmanager/supervisor，不只创建 controller map。
2. 每连接独立端口、私有 state、凭据引用、健康检查、Job/进程身份和启动取消。
3. 接入全局/每连接 admission，统一限制同时请求、排队、执行、打开句柄、输入/输出及 wire bytes；全局 gate 不能分别放在各 MCP 子进程内自称全局。
4. 单连接 start/stop/reconnect/disable/remove，错误隔离及启动事务失败清理；不杀陌生端口进程。
5. 完成多连接必需的健康检查、退避重试、人工停止抑制重试、认证失败熔断和 sleep/wake；同条连接不能同时启动两个 retry worker。
6. 保存多套 OpenAI/Cloudflare 配置并支持并行实例；同一公共入口不能仅靠 URL 自报身份隔离。

验收：A/B 同时真实读文件；A 故障、停用、改独有规则、撤销或重连时 B 继续工作；端口冲突不会接管其它进程；崩溃和取消不留 orphan；不同 ingress 之间不复用 cursor/确认/结果。

两条真实外部 Tunnel 的同类组合和可用的混合组合须另有证据，不能用 fake readiness 代替。缺凭据、账号或网络环境时记录未验收项；外部 ChatGPT 多账号验证与本地双 SDK client 验证分开。

### R11 03 受限命令后端

对应原计划：P08。

1. 接通可信 broker、networkguard、worker 文件访问控制和执行期映像身份检查。
2. 复用 commandexec/confirmation/commandpath；将 fixed_command 从配置解析升级到真实执行。
3. 串起 prepare、local approve/reject、execute、status、cancel 和 expire。审批显示连接、模板、输入范围、副作用及限额。
4. 配置允许的 native 程序和 reviewed variants；参数只能按类型构造。私有输入区、最小 env、闭 stdin、无可见控制台；探针禁止子进程，脚本/构建另设允许的进程树和资源规则，全部默认离线。
5. 有界 stdout/stderr、CPU/内存/时限和完整进程回收；默认返回审查过的结构化结果，原始输出不得进日志/诊断。
6. 安全审计准入/开始必须满足规定的持久化要求；audit 不可用阻止新执行，不能用“已进入异步队列”假称启动前已落盘。

验收：真实固定非版本命令产出可核对结果；未授权连接/模板/文件、旧确认、重复确认、参数注入、映像替换、联网、读秘密文件、未授权写入和子进程逃逸被拒绝；超时、取消、broker/目标崩溃后清理完成且其它连接正常。

### R11 04 工具版本探查后端

对应原计划：P08。

1. 继续使用无进程 discover_tools 查找已配置候选；候选存在不自动授予执行权。
2. 原生工具经绝对路径、身份 pin、固定 argv、私有目录/env 和逐次本机确认进入相同执行链。
3. 至少两个真实工具版本得到验证；Go/Node 等可作为首批候选，具体依赖及兼容性以实测固定。Python/Git/Codex 的 native 可执行文件按兼容性逐个加入；wrapper 不假装原生探针，需走独立、批准过的脚本执行链。
4. 返回 exists、version、unsupported、timeout、version_unrecognized 等准确状态；输出无法解析时不猜版本，不返回完整机器路径或 env。

验收：标准输出/错误输出版本格式、非零退出、空输出、编码错误、版本无法解析、超时、同名假程序、秘密环境注入、包管理 shim、联网尝试均有测试；实际版本与操作者本地对照一致。

### R11 05 工作文件写入和 patch 后端

对应原计划：P04、P14。

1. 新建受授权 root 约束的写入模块，与配置 FileStore 分离；完成 create/replace、文本 patch 和强内容版本。
2. prepare 返回具体目标、diff、影响范围和内容摘要；本机确认与写入原子边界绑定，内容或权限变化需重新 prepare。
3. 实现临时文件、Windows 原子替换/失败恢复、逐文件锁和路径身份验证；测试普通并发进程修改及 reparse/链接交换，不仅测试应用内部锁。
4. 返回逐项结果，维护有界恢复记录；恢复需要当前版本匹配。通过同一接口处理任务修改和产物写回，禁止任务直接绕过。

验收：真实授权目录新建/更新/patch 内容正确，旧版本及只读连接被拒；中文路径、编码/换行、文件占用、磁盘满、并发修改、部分失败、进程被杀及恢复通过。创建写入工具但不能真正写原项目不算完成。

### R11 06 用户自选脚本后端

依赖：R11 01、R11 03、R11 05；本阶段必做。

1. 加入 script_task 与解释器注册表；PowerShell、Python、Node.js、cmd/bat 分别使用实际运行时和明确参数规则。不能全局放开 shell command 字符串。
2. 支持本机导入、选择或在授权项目内新增脚本；允许自由业务脚本内容，不限制为有限预置功能。批准的入口文件和任务输入为不可变副本，禁止运行时悄悄换成另一份代码。
3. 本机审批展示脚本内容、运行时、参数、读写范围、允许的子进程、资源和离线策略；模型不能批准自己生成的脚本。
4. 处理多文件脚本和导入依赖、版本冲突、编码、空间/中文路径、错误输出、超时和取消；所有后代进程继承权限/网络约束。
5. 结果和可写副本变更形成独立清单，经写回审批后真实应用；拒绝写回不丢失可供查看的任务结果，但有保存限额。

验收：四类已配置解释器各完成真实脚本成功、失败和取消用例，至少一个多文件/导入用例；用户可运行自己新增的非预置脚本。修改脚本后旧确认失效，访问主机秘密、写项目外、联网、无限子进程/输出被阻止。不具备运行时只能记环境待准备，不能据此把必做脚本能力结项。

### R11 07 项目构建和测试后端

依赖：任务执行与写入后端；本阶段必做。

1. 加入 project_task：授权项目、可核对输入 manifest、toolchain、build/test 入口、参数、依赖/缓存范围、输出目录和产物策略。
2. 从已批准的项目副本执行构建/测试，支持原生编译器、package scripts 和必要子进程；不能只运行探针或禁止所有 compiler/helper。
3. 支持离线依赖准备与可复用的受控缓存，缺依赖准确报错；网络获取、安装器或跨项目凭据不自动启用。
4. 独立设置较长任务时限和进程树/内存/CPU/磁盘限额；一条连接的长构建不饿死另一条的读取或任务。
5. 提供有界进度/输出、真实 build/test 退出状态、测试范围、产物清单及内容摘要；支持取消、失败产物保留和按批准清单写回/导出。

验收：至少一个真实 Go 项目编译生成可验证产物，测试成功与预置失败用例均准确报告；至少一个 Node 或 Python 项目验证项目任务及脚本/子进程链。还需有非 helper 的本项目副本构建/测试验证。取消时整个树退出，宿主源目录未经写回批准不被改；有授权的产物能写回，外部修改冲突拒绝覆盖。

### R11 08 后端 MCP 集成和综合验收

对应原计划：P05、P08、P09、P10、P13。

1. 用本地管理 CLI 完成七项功能，不依赖 GUI。确认只能来自本机受控 IPC。
2. 最小 MCP 工具面建议保留 run_probe，增加 run_command/run_task 的 prepare/status/cancel，以及 write_file/apply_patch 的预览和提交链；具体 schema 在 R11 00 冻结。脚本和 build/test 共享任务协议，不建重复队列。不添加远程 approve、权限编辑或任意管理接口。
3. tools/list 按当前授权和真实 capability 过滤；普通只读连接不能获得写入或执行能力。读、写和项目代码执行工具的 annotation 分别定义，不把脚本/构建声明为只读。
4. 至少两个真实 MCP 子进程、两个 SDK client 完成不同授权范围和并发命令/读取链；请求体、CallToolResult 与完整 JSON-RPC wire budget 分别验证。
5. 一小时有界混合负载与故障注入：并发读取/写入、规则变更、脚本、build/test、待确认/取消、重连、worker/Tunnel 崩溃、暂停恢复；记录具体进程数、句柄、RSS、队列、磁盘使用、丢日志和错误。
6. 实际执行 Go test/race/vet、相关 fuzz、Windows OS 集成及需要单独授权的隔离测试。fake、skip、cached、cross-build、真实执行记录分开。

后端 Gate B：七项真实功能验收均通过；没有越权、未授权写入、越界执行/联网、跨连接混淆、确认重放、预算失控或无法回收的子进程。必须验证原文件真实写入/patch、用户自选脚本、真实编译产物与真实测试成功/失败。测试 helper、mock 和 capability stub 不算真实交付。失败或未验收功能不能进入 GUI 的“可用”状态。

### R11 09 GUI 接入和前端测试

依赖：Gate B 通过。本步骤以前不改现有前端交互来伪装后端进度。

1. 保持现有五页布局与颜色、字体风格、右键复制和刷新行为。
2. 历史连接逐行展示独立状态/start/stop/reconnect；选中 A 查看详情不停止 B。
3. 高级模式加入连接/profile/命令/root 授权、可验证 executable 选择、规则表单、本机待确认队列、结果与取消；JSON 编辑保留为高级选项，不作为唯一入口。
4. 工具页/高级区域展示实际版本和明确失败原因，不能只显示文件候选数量。
5. 文件规则支持 deny/ignore 分组编辑、预览、影响连接说明和确认；避免把 ignore 标成访问拒绝。
6. GUI 刷新或重开不重复提交命令；待确认和执行由后端持有。退出 GUI 和停止后端的语义明确，不静默遗留命令。
7. 增加 VM、原生桥接和真实 WebView2 集成测试；复测 DPI、侧栏收展、长名称、空列表、英文及错误状态。
8. 在已有布局内加入文件 diff/写入确认与恢复入口，脚本选择/新增/执行审批，以及 build/test 任务状态、输出、取消和产物写回。明确显示 read/write/execute 三种授权，不用单个“高级模式”开关授予全部权限。
9. 待确认视图能够展示脚本/patch 内容，不仅显示模板名；长任务刷新、GUI 重开、连接切换不丢状态或重复执行。

### R11 10 人工验收和可回退交付

对应原计划：P12、P13。

1. 使用者按顺序验收：两条连接并行 → 修改 A 的规则/B 不受影响 → 批准版本及固定命令 → 新建/patch 原文件并制造版本冲突 → 选择/新增脚本 → 真实 build/test 成功与失败 → 查看并批准产物写回 → 长任务取消 → 撤权与单连接恢复 → 工作文件恢复及配置备份重开。

4. 输出新 EXE/便携包、校验和、后端/GUI 验收记录和已知限制；含 broker 的发行形态需相应签名/来源审查，不能把未签名 helper 当已可信发布。
5. 仅修改事实状态文档中本轮证据覆盖的部分。没有真实账号、安装和独立审查证据时仍标私有测试版，不宣称正式稳定版。

## 六 其它功能的取舍

| 功能 | 本阶段决定 | 理由和重新进入的条件 |
|---|---|---|
| 元数据索引/SQLite/FTS/embedding | 不开发，不接线，不作为七项交付依赖 | 当前已有直接搜索；历史局部 direct/catalog 对照记录未显示 live-verify 后的端到端收益。将来重复查询明显慢且基准证明收益时再考虑 |
| 外部 rg 加速整个项目搜索 | 不默认替换现有搜索，可作为批准的固定命令兼容性样例 | 命令权限不等于安全搜索：仍需 deny/ignore、编码、覆盖率、分页、输出预算与取消。不得用原始 root 路径绕过 policy |
| 独立 Git status/diff | 延后 | 原生 Git 仍有项目配置、filters 和输出边界问题；有固定命令模板不意味着安全 Git 查询已自动完成。用户频繁需要且具体 profile 审查通过时再纳入 |
| 独立更新服务 | 延后 | 不提升当前核心链；先保持手动版本交付与回退，避免新增联网、签名及安装复杂度 |
| 从 agent config.toml 导入 | 延后 | 当前目录浏览已能完成授权；导入只减少初始化步骤，不解决本阶段七项核心缺口 |
| 完整 doctor/自动修复产品 | 延后完整产品，保留必要后端诊断 | 版本/身份/端口/隔离缺失的诊断是本阶段依赖；不自动改系统权限、修网络或安装组件 |
| supervisor 和必要自动恢复 | 本阶段必需，不延后 | 多连接故障隔离、停止和回收的基础；不做整机自愈或未经授权的自动启动 |
| GUI 清晰度跨机验证 | GUI 验收必需，不重写已完成 DPI 修复 | 用户已明确要求不同电脑清晰，第二台和双屏证据仍欠缺 |
| write_file/apply_patch、构建测试、用户自选脚本 | 本阶段必交付 | 按用户最新要求提前实施，使用独立权限、内容确认、项目副本与受控写回；不再延后 |
| 联网命令、依赖下载、自动安装、系统操作 | 不默认纳入 | 构建/脚本默认离线；需要时单独确定范围并授权，不能由脚本开关自动获得主机网络或管理员权限 |
| 安装器、自动启动、跨平台 GUI、公开插件市场 | 延后 | 本阶段以 Windows 私有可用版本为目标；只提供必需的可选 broker 安装/卸载和便携交付 |

不实现索引是本阶段的取舍，不是判定索引永远无用。命令行的 rg/find 同样可能全量扫描；权限只回答“能不能执行”，不回答“是否更快、结果是否完整”。

## 七 执行约束和停止条件

- 用户已确认执行；主 agent 直接处理，不继承早期 Luna 委派。当前完成的是规则管理第一增量，隔离契约与真实执行硬门尚未闭合，不据此跳过 R11 00 或宣称完整 R11 可用。
- 不自动安装服务、提升权限、改变 WFP/防火墙、下载程序或申请外部凭据。这些动作到需要时单独说明具体影响并取得授权。
- 七项均是必交付项；不允许用“保持关闭/未接线/模拟通过/只改临时副本”结项。如果隔离路线无法成立，提交明确阻塞原因和替代设计供裁决，不降低硬门。支持用户自选脚本不等于没有权限边界或无需内容确认的远程 Shell。
- 不覆盖当前可用 EXE，不停用用户现有 GUI；真实进程和系统隔离测试使用专用配置/端口/临时目录，避免接管用户正在使用的连接。
- 不承诺未经验证的订阅/账号能力；缺真实 Tunnel、多账号、跨机测试环境时保留对应验收项，不能写 PASS。
- 一旦出现越权、未经批准的工作文件写入/覆盖、脚本或子进程逃逸/越界联网、凭据泄漏、影响无关连接/正常程序或无法回收的进程，立即停止相关执行入口并修复。经批准的写入本身不再是停止条件。
- `.planning` 中早期桌面阶段状态并非当前事实来源，本轮不运行旧 GSD 自动脚本或将规划写成已完成。实际阶段记录以本计划任务 ID 和新的验证证据为准。

## 八 设计依据

仓库基线：`MASTER_PLAN.zh-CN.md`、`IMPLEMENTATION_STATUS.md`、`NEXT_PHASE_PLAN.zh-CN.md`、`R4_WINDOWS_NETWORK_DENY.md` 以及上述实际源文件。

Windows 官方资料只支持原语及限制，不证明本项目实现已安全或某工具兼容：

- [AppContainer isolation](https://learn.microsoft.com/en-us/windows/win32/secauthz/appcontainer-isolation)：资源及网络隔离需要操作系统边界，不能由 cwd 字段代替。
- [Launch an AppContainer](https://learn.microsoft.com/en-us/windows/win32/secauthz/implementing-an-appcontainer)：AppContainer/LPAC、身份和访问控制的候选实现依据，不要求所有工具采用该路线。
- [WFP Object Management](https://learn.microsoft.com/en-us/windows/win32/fwp/object-management)：动态会话对象随会话结束移除；这也要求本项目验证 broker/会话异常时 worker 不继续失去保护地运行。

本轮计划不选用未核实的新库。执行中涉及现有 Go SDK、Windows API/CLI 具体用法时先获取对应版本的官方文档；可用时按仓库要求用 Context7 resolve/query，没有该工具时用官方原始文档核验并记录限制。
